# 今後の実装方針と未決事項

これは次の作業を選ぶための方針と候補であり、全項目の着手命令ではない。現在のユーザーの依頼を最優先し、対象・非対象・検証・互換性を決めた有限の作業単位で進める。直近の例外書式/別判型は実装済みで、そのタスク文書を恒久的な「現在の作業」にしない。

## 次の仕事を選ぶ基準

原稿導入→標準の紙面→必要な調整→保存/出力の短い経路をまず守る。実ユーザーの迷い、データ損失の危険、実書籍で再現できない表現、出力の用途に対して不足する項目から優先する。ボタンやプリミティブを増やすこと自体を進捗にしない。

## 段階ごとの候補

| 段階 | 狙い・候補 | 始める前に確かめること | 合格に必要な証拠 |
| --- | --- | --- | --- |
| 体験の検証 | 人間による原稿導入・全体/局所変更・SNS出力の操作評価。実機スマホ/キーボード、他エンジン | 実ユーザーの目的、短い評価シナリオ、検査端末 | 迷った箇所と結果を分けた観察。幅だけの合格を実機へ読み替えない |
| 日本語組版の改善 | 約物詰め・ぶら下がり・長いルビ・孤立行・欧文/数字/URL・欠字 | 実書籍/最小反例、元文字保存、フォント字形とメトリクス | 独立fixture、行/ページの不変条件、共通描画と出力の目視 |
| 本づくりの改善 | 多段階目次・索引、画像キャプション、全継承経路の可視化、素材のフォルダー/タグ管理 | 既存スタイル/Scope/テンプレートで表せるか | 構成の追加/移動/削除、再組版・JSON・保存の往復 |
| 印刷用出力 | 文字/ベクトルPDF、フォント埋め込み、塗り足し/TrimBox等、プリフライト | 出力対象、字形・色・寸法、PDF.js素材のラスタ化との差、検査可能な仕様 | 実PDFの埋め込み/寸法/描画、未検査の明示。PDF/Xや入稿保証は別判定 |
| 特別な範囲 | 容量を変える物理ページOverride、異判型混在、左綴じ等 | 再ページングによる適用先循環、意味的範囲で代替できるか | 境界固定/明示的な構造変換/収束規則と非収束診断 |

表の順序は検討の順序で、確約したリリース日程ではない。たとえば新しい原稿で不具合が見つかれば、広い新機能より再現と修正を先にする。

## 採用していない・未決の項目

サービス名、リッチ編集をどこまで持つか、文字PDFの実装方式、正式な印刷出力プロファイル、容量を変える物理ページ範囲の規則は未決。コマンド検索、多言語、追加テンプレートも必要な作業が示されてから検討する。

脚注・高度な章構造・タブ/リーダー・多言語の組版は将来候補。アカウント・クラウド同期・AI執筆/校正・共同編集を、ロードマップの既定項目にしない。通常本文の座標編集へは進めない。

## 実装に進める手順

1. ケースと利用目的、困っている挙動を [CASE_CATALOG](CASE_CATALOG.md) へ記録する。
2. 既存プリミティブで表せるか、テンプレート/自由/外部ページで十分か検討する。
3. 有限のタスクに対象・非対象・保存互換性・要件ID・独立した期待値を置く。
4. 不具合なら修正前の失敗を記録する。仕様変更なら理由とユーザーの選択を [DECISIONS](DECISIONS.md) に残す。
5. 実装・関連検査・目視/実出力を行い、CAPABILITIESと正本を更新する。完了した計画は履歴へ移す。

対応範囲は [CAPABILITIES](CAPABILITIES.md)、完了ゲートは [ACCEPTANCE](ACCEPTANCE.md)、履歴の所在は [history/README](history/README.md)。原本の将来案をそのまま現在の合格条件へ追加しない。
