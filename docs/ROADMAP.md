# 品質向上のロードマップ

更新：2026-10-21。優先順位と未着手の仕事を選ぶための正本。全項目の一括着手命令やリリース日程ではない。現在の対応は [CAPABILITIES](CAPABILITIES.md)、採用原則は [PRINCIPLES](PRINCIPLES.md)、技術候補の根拠は [2026-10-21の調査](research/2026-10-21-typesetting-and-output.md)。

## 目標と優先順位

原稿を入れ、自然な紙面を確認し、必要な例外だけ調整して出力する短い経路を守る。その上で、日本語組版の品質、本の仕上げ、外部素材、印刷用出力を段階的に完成へ近づける。機能表の項目数より、利用者が一つの本を安全に完成できることを優先する。

| 優先度 | 判断 |
| --- | --- |
| 最優先の不具合 | 再現する本文欠落・保存破損・出力の不一致が見つかったら、新機能より先にfixtureと修正前の失敗へ変える |
| P1 | 広い用途へ効く品質、原稿保護、再利用方針を決める先行試作。印刷出力の基盤も早く不確実性を減らす |
| P2 | 本を完成させる調整、表現・出力の拡張。対応原稿や具体的な不足があれば順序を上げる |
| 条件付き | 新しい利用目的を確認して選ぶ。既定の開発範囲や現行の合格条件へ混ぜない |

「未着手」は採用候補として切り出せる仕事、「要試作」は方式・統合・配布条件の確認が先、「計測後」は性能上の問題を測ってから実装を選ぶ仕事。人間の評価・実機・入稿先での確認が必要なものは、機械検査で代用せず明記する。依存は本実装の受入前提で、調査や小さな試作まで禁止するものではない。

## 実装済みとして重ねて作らないもの

共通スタイルと全体/見出し/範囲の書式、GUI書式の原稿への投影、改丁、構成のドラッグ/キー移動、自由ページと開始テンプレート、素材差し替え、目次の自動多頁化、PNG一括/範囲ZIP、操作検索、組版Worker、可視ページの遅延描画は既存機能である。残る不足だけを下表で扱う。操作検索は本文検索ではなく、画像PDFは文字/印刷用PDFではない。

4. **RM-00/23/24で負荷と実利用を評価する。** 現在の操作検査を人間/実機や最大容量の実測へ読み替えない。

## 再利用と採用の判定

標準/API → 既存エンジン/ライブラリ → 同一条件の最小試作 → 統合/保存/出力の確認 → 採用理由、の順で進める。第三者依存は版・配布物・ライセンス・ハッシュ・保守状態を確認する。導入だけを成果にせず、解けたケースと残った不足を記録する。

再利用を優先しても、共通のBook Model、意味的な範囲、ローカル処理、原文保護、プレビュー/出力で同じページ境界という条件は保つ。既存ライブラリが合わない場合は、失敗した試作と不足を示し、不足する規則と製品固有の接続へ自作範囲を絞る。詳細と参照先は [技術調査](research/2026-10-21-typesetting-and-output.md)。

## 一つの作業を完了する条件

1. [CASE_CATALOG](CASE_CATALOG.md)でケースと未達を確認し、対象・非対象・依存・利用者を決める。実書籍を見ていなければ合成案と明記する。
2. 方式の試作が必要な項目は、共通fixtureと独立した期待値で候補を比較する。採用・保留・不採用理由を残す。
3. 実装へ進む範囲だけ要件・現行の仕様正本・保存形式・入力投影・解除/Undo・診断・出力の契約を更新する。将来候補を対応済みへ移さない。
4. 不具合なら修正前の失敗を残す。変更後は関係する回帰と、実装に応じた操作・画像・実出力を確認する。
5. 文書/ハーネスはverify:harness、プロダクトの完了は [ACCEPTANCE](ACCEPTANCE.md)のverifyで判定する。表示・自動検査・人間/実機・規格/入稿検査を区別する。
6. 実行環境・指紋・コマンド・終了コード・証拠・未達をoutputへ残し、採用理由を [DECISIONS](DECISIONS.md)、現在の対応を [CAPABILITIES](CAPABILITIES.md)へ反映する。完了項目は現行対応へ移して台帳から除き、経緯を [履歴](history/README.md)へ残す。
