# 完了条件と合格の意味

## 対象と対応表

現在の完了ゲートは `harness/config.json` の `phase: mvp`。R-01–R-50を対象とする。要件、fixture、機械検査、目視項目、現行の仕様正本への対応は [requirements.json](../harness/requirements.json) の一か所で管理する。過去のslice-1（R-01–R-10）の成功や、ロードマップ全体の完成と混同しない。

| 契約群 | 必ず確かめる結果 |
| --- | --- |
| 原稿導入・交換 | 貼り付け/TXT/Markdown/DOCX/JSON、軽微修正、未知文字と元本文の保護 |
| モデル・参照 | 正本AST、安定ID、構成と原稿の一致、孤立参照の診断、未完draft保護 |
| 組版 | 標準A6、自動多頁、長文/Unicode、独立禁則、ルビ/圏点/ダッシュ、縦横一二段 |
| スタイル・範囲 | 継承、部分余白、局所変更/解除、章の追従、構造アンカーと固定頁の区別 |
| 特殊ページ・画像 | 3表現、追加/ドラッグ/キーボード移動/削除/変換/自由ページの要素操作、フロー/独立/見開き画像、混在後の本文再開 |
| PCの操作 | 初回原稿、折返し/編集幅、端の開閉/リサイズ、本/共通書式/選択範囲の設定、3表示 |
| スマホ幅 | 320/375px、16px入力、横はみ出しなし、タブ/ページ移動、PNG生成/保存経路 |
| ローカルと保存 | 外部原稿送信なし、素材原本/IndexedDB、JSON、再読込、移行退避/破損保護 |
| 出力 | 同じ確定ページ列、実判型/300dpi、PNG/PDF/ZIP/見開きの全ページ対応 |

各群の具体的な対応範囲・制約は [CAPABILITIES](CAPABILITIES.md)、組版の期待値は [TYPOGRAPHY](TYPOGRAPHY.md)、操作は [UI](UI.md)。未対応属性が型にあるだけでは合格にしない。

## 二つのゲート

`npm run verify:harness` は検証基盤の合格。lint、依存境界、テストポリシー、実際の `tsc --noEmit`、文書/原本/fixture/要件整合、検査器の自己テストを実行する。アプリの完了判定ではない。

`npm run verify` は上記にビルド、実装に対するモデル/組版テスト、ブラウザの操作、固定環境の画像比較、実出力の解析、目視証拠を加えたプロダクトの完了ゲート。途中で失敗したら停止し、後続を成功扱いしない。全工程の終了コード0と同じソース指紋の証拠が必要。

## 独立した検査と鮮度

- 元の共有仕様原本と固定fixtureのハッシュ、10万コードポイントの長文、Unicode・制御文字を保つ。
- 禁則の期待値はfixture側の独立値。実装の集合を正解にしない。
- 要件にはfixture、機械ルート、目視ルート、現行仕様文書を接続する。履歴の計画を現行正本へ接続しない。
- visualの許容差は現在0画素。基準更新は対象ごとの目視と理由の記録を伴い、その後の通常比較が必要。
- 実出力manifestは現在のソース指紋とphaseで生成する。古いPDF/PNGをコピーして現在の証拠へ見せかけない。
- 指紋は実装だけでなく文書・検査・固定依存も含む。文書だけの変更でも証拠の鮮度を確認し、プロダクト全体を合格とするならゲートを更新する。

## 出力の合格範囲

`pdfProfile: raster` で、アプリから実際に保存したPNG/PDFの判型・ページ数・300dpiを解析する。PDF内の全ページ画像、単ページPNG、ZIPの全PNG、見開きの左右を画素比較する。現在の構成はA6/B6/A5の6案件・21ページ。ファイル本体を画面に表示した目視も行う。

これはRGB画像PDFの一致であり、文字検索・文字フォントの埋め込み・PDF/X・CMYK・塗り足し・印刷所の入稿合格を意味しない。現在の出力検査器はrasterのみ。`text` プロファイルを選ぶだけでは対応せず、未対応エラーで停止する。文字PDFへ進むには実装と検査器、実PDFの埋め込み/字形/描画検査が必要。

## 目視と実操作の5項目

`harness/manual-review.json` にdefault-page-quality、vertical-glyphs-and-spacing、mobile-usability、export-appearance、local-firstの5項目を記録する。各項目のpass、証拠ファイル、レビュー者、環境、現在のソース指紋が揃わなければ全体ゲートを通さない。

見た目の読みやすさや操作の意味をAIが確認したことと、人間のユーザビリティ調査を分ける。ブラウザ幅と実機のキーボード、ChromiumとSafari/Firefoxも分ける。目視のpassを未検査範囲へ拡張しない。

## 報告

合格・失敗・未実行・未対応・手動待ちを分け、実行したコマンド/終了コード/環境/指紋/証拠/限界をoutputへ保存する。現在の結果の読み方は [QA](QA.md)、実行手順は [HARNESS](HARNESS.md)。将来機能の未実装は現行合格の否定ではないが、未達を隠す理由にもならない。
