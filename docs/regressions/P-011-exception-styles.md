# P-011 — 例外書式の解決と同一ページ出力

## 追加ケースと初期の失敗

`fixtures/book/style-exceptions.md` と `tests/product/style-exceptions.test.mjs` を先に追加した。旧ビルドに対する `node --test tests/product/style-exceptions.test.mjs` は終了1、7ケース中6失敗。Page/Sectionの保存属性が拒否され、文字属性は文字列のまま、章の横書き/二段・画像配置・自由ページ整列も存在しなかった。

継承後の余白は部分オブジェクトを単純に置換してはいけない。Book→章の順序、Page/Sectionの部分余白、局所指定、リセットを独立した期待値で検査した。単語の数字は原文に保持し、漢数字は描画時の生成文字に分けた。SVGの文字が一字ずつのノードになるので、初期の連続文字列検索は表示を正しく検査できなかった。変換対象のノード文字を抽出し、独立した「二〇二六」と比較する検査へ修正した。

追加された11番目のケースは、章の上余白を5mmにして柱を8mmに置くと `Missing expected exception` で終了1だった。柱を全体余白だけで検査していたため。解決後のPageStyleで、実際に表示される柱と番号の位置を検査するように修正。非表示の柱との衝突でエラーにしない。

## 大きな次段落のKeep with next

二段・一段4行の狭い版面で、次段落に14ptの文字と前余白を指定したfixtureから、見出しのあるページに次段落がないという失敗を再現した（`local character metrics…`、終了1）。次段落を全体の一行として見積もっていた。実際の字サイズ・行送り・段落前余白を先読みして予約するよう修正し、文字保存と生成座標の検査を維持した。

## 操作テスト

最終レビューで、英字の横倒しを日本語とルビを含む範囲に指定すると、日本語まで回転するケースをfixtureへ追加した。`local orientation…` は終了1（`Latin direction overrides must keep Japanese text and ruby upright`）。向きの局所指定は英字・数字へ適用し、日本語・句読点・漢数字表示・日本語ルビを通常の縦書きへ戻すよう修正した。AST上の指定と原文はそのまま保持する。

正立英字と白丸圏点の組み合わせもfixtureへ追加し、圏点中心が文字セルの中央からずれることを独立座標で確認（同テスト終了1）。正立字の全角セルを使用して中心を計算するよう修正した。任意寸法はPC/375pxの操作テストへ150×210mmと149.5×210mmを追加。通常の入力・確定・保存・再組版は終了0。IAB自動操作の数値fill直後には確定されず、キーによる入力で確認した。これをアプリの寸法検証の不具合とは数えない。

文字書式の「適用する」は、文脈操作の透明背景が主操作の背景色を上書きし、白文字が読めなかった。IABの375px目視後、背景と文字の輝度比を独立計算する操作検査を追加。PC/375pxとも1.045（必要4.5以上）で終了1。主操作の背景を復帰し、元の失敗画像を `output/exceptions/ui/before-character-*.png` に退避した。範囲・書式・保存の期待値は変更していない。

既存31フローの初回は29成功/2失敗。局所詳細の中に新しい詳細を入れたため、`#block-local-details summary` が2個を指す厳密セレクタの失敗だった。直下のsummaryを選ぶよう接続点だけ修正し、本文・ID・書式・JSONの期待値は変更していない。

新しい操作フローの初回は2成功/2失敗。見開きの最初のDOMノードは隣の章だったため、章の紙面を通しページで明示する検査へ修正。画像がある作業はIndexedDBへ保存する契約なのにLocalStorageのポインタからprojectを読んでいたため、実保存先を読むよう修正した。いずれも実装の期待値に合わせて弱めたのではなく、適用先と保存契約を正しく観測する変更。
