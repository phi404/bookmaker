# P-012 — 操作検索の終了とスマホの共通履歴

これは2026-10-12のGUI改修中に見つかった回帰の記録。現行操作の正本は [UI](../UI.md)。

- ID / 関連要件：P-012、R-30/R-35/R-42。
- 発見日 / 環境：2026-10-12、Windows、Node 24.19.0、Playwright 1.63.0、固定Chromium。
- 再現入力 / 画面：操作検索へ「存在しない操作」を入力してEscape、1440×900。Book workspaceの奥付→自由ページ→要素編集→Undo→Redo、375×812。
- 起きたこと：検索のEscapeで閉じず、元のボタンへフォーカスが戻らなかった。スマホのRedoがレスポンシブCSSで非表示になり、共通履歴を画面から使えなかった。
- 期待：Escape一回で検索を閉じ、操作位置へ戻る。Undo/Redoはスマホでも使用でき、同じBook Modelの編集を復元する。
- 修正前の失敗：`gui-workbench.spec.mjs` の検索復帰、`book-workspace.spec.mjs` の375px共通履歴が終了コード1。検索のtrace/画面は `output/gui-redesign/escape-focus-before`、全体ログは `output/gui-redesign/initial-flow-failure.txt`。
- 原因と修正：検索入力のkeydownでEscapeを明示処理し、既定動作を止めてnative dialogを閉じる。スマホのRedo非表示を撤回し、書名を可変幅にして履歴・検索・出力を収める。左端ビューと操作検索にはキーボード操作/選択のARIAを付ける。
- 修正後：全39件の操作検査が終了コード0。検索の入力/↑↓/Enter/Escape/フォーカス復帰、元のスマホ共通履歴検査を保つ。文字/ページ/JSONの期待値を緩和していない。
- 視覚基準：矢印文字をLucideアイコンへ変更したため、独立した左右/上下の期待値をアイコン属性へ接続した。実際のページ番号と見開き左右の検査は維持。各旧/新/差分を目視して理由を記録し、通常の0画素比較で再確認する。
- 確認範囲：固定ChromiumのPC/320px/375pxとアプリ内ブラウザ。iOS/Android実機、ソフトキーボード、スクリーンリーダー、人間のユーザビリティ調査は未実施。
