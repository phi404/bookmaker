# 現在の対応範囲と制約

2026-10-21の本の仕上げと表示の改修までを反映した一覧。この文書は現在の挙動を定義する。**実装あり**と**この変更状態で検証済み**は別で、最新の合格は [QA](QA.md) からソース指紋を確認する。今後の候補は [ROADMAP](ROADMAP.md) に分ける。

## 原稿・本の構造

| 機能 | 現在の対応 | 主な要件 |
| --- | --- | --- |
| 入力・軽微修正 | 貼り付け、折返し入力、TXT/Markdown/DOCX/作業JSON、原稿画面へのファイルドロップ。初回は原稿、任意サンプル | R-01, R-21, R-35, R-42 |
| 原稿の修正移動 | 紙面から描画単位/ルビ読みへの明示ジャンプ、原稿文字列の検索・範囲/一件/全置換、紙面の一致表示 | R-47, R-48 |
| 文書 | Section / 段落 / H1–H3見出し / 改ページ・改丁 / Text / Ruby / 特殊ページ参照 | R-02, R-12, R-22, R-28 |
| 編集の正本 | Book Model v3。原稿・構成・素材・GUIの往復、共通Undo/Redo、ID保持 | R-23, R-28, R-30, R-31 |
| 入力途中 | 未完・重複などの既知特殊参照は別draftとして保存。最後の有効紙面を表示し、上書きや出力を止める | R-29 |
| 構成 | 章/自由ページ/自動目次/素材ページの追加、構成のドラッグ移動・Alt+上下・削除・複製。章内の特殊ページを階層表示・開閉。章の現在ページ範囲は組版結果 | R-31 |
| 保存 | LocalStorage / 素材付きIndexedDB、ファイルメニューのJSON保存/再開と保存後の新規作成、JSON全作業往復、旧形式1/2の移行・原値退避・破損保護 | R-14, R-22, R-34, R-49 |

TXTはMarkdown記号を勝手に解釈せず、旧テキスト解釈で構造化してから保護して投影する。DOCXは段落・見出し・ルビ・圏点・手動改ページの意味を取り込む。Wordの版面・自動改ページ・フォント・画像の再現はしない。変更履歴やXML実体は拒否する。交換の詳細は [SOURCE_FORMAT](SOURCE_FORMAT.md)。

## 確認・出力・端末

PCは左端の原稿/構成/素材、中央の紙面、本/書式/選択の設定。左右は開閉・リサイズ可能。中央は見開き/単ページ/一覧と表示拡大、一時的な集中表示。操作検索・キーボードから既存のビュー/設定/出力へ移れる。ライト/ダークはUIだけを変更し、紙面は不変。紙色は白が初期値。「ページの組み方」は左右の余白と開始面の扱いを選び、余白の数値・番号・紙色・組方向を変更しない。画像レイアウトは1080×1080、1080×1350、1600×900 px相当・16ptを明示選択できる。表示モードと版面規則は独立する。取り込み中は最後の紙面を完成扱いせず出力を待機させる。空原稿は待機表示にし、画像/PDF出力を無効にする。R-42。

保存はタブ間で排他し、別タブの新しい作業を古い保存で上書きしない。素材付きは新しいスナップショットの確定後に参照を切り替える。容量不足/競合時は入力を保持し、自動保存を停止して作業JSONを案内する。Web Locksを使えない環境も停止する。組版の依頼は処理中と最新の保留に集約し、古い結果を完成として表示しない。R-49, R-50。

PDFは見出し1〜3の階層しおりと自動目次の内部リンクを持つ。範囲外の宛先は省き、含まれる下位見出しは必要に応じて上位へ繰り上げる。PNGは300dpiで1ページ・全ページ/範囲ZIP・見開き。一括PNGを常設し、対象範囲はPDFと共有する。PDFは選択した仕上がり寸法のRGB画像PDF。共通ページ列と同じSVGを使い、範囲出力でも通しページの対応を維持する。出力をキャンセルでき、保存/開くリンクを残す。編集・出力対象が変われば旧リンクを消し、処理中の変更を旧内容の完成として保存しない。PDFの検索可能な文字・フォント埋め込み・PDF/X・CMYK・塗り足しを含むページサイズは未対応。

独立した実出力検査はA6/B6/A5、左綴じと階層目次を含む。対象ファイル・件数・範囲PDFは検証manifestと実行記録で確認する。その他の判型はモデル/操作の対応と区別し、最大寸法での大量出力を実測済みとしない。判型・プリセットの変更で本文を変えず、組版プリセット再選択は文字/行送り/余白/自動字数・行数を再設定し、柱・番号を保持する。画像レイアウトは別の明示操作で、余白の規則・寸法・文字・余白・番号を画像向けに変更する。

固定ChromiumではPC、1024px、375px、320pxの操作・画像を検査する。スマホ幅の操作は画面切替・ページ移動・PNG生成まで対象。iOS/Android実機・ソフトキーボード・Safari/Firefox・人間のユーザビリティ調査は未実施。アプリ内ブラウザのPNG準備・リンク確認と、Chromiumの実ダウンロード検査は別の証拠。

## 容量と数値の契約

- 原稿は50万UTF-16コード単位まで。長文検証は10万コードポイントのfixture。ファイル容量制限とは別。
- 任意用紙は幅60–350mm、高さ60–500mm。基本本文7–18pt、行送り倍率1.55–3、余白5–70mm。版面に本文が入らない組み合わせは拒否する。字数/行数1–200は実容量を超えない上限指定。
- 文字局所指定は5–36pt、字間0–1em。自由ページ文字は5–72pt。異なる用途の範囲を同じ上限として扱わない。
- DOCX入力32MiB、本文XML8MiB・対象XML合計12MiB。素材原本1件16MiB、PDF20ページ、PDF表示画像のdata URL累計48MiB。
- 素材100件、特殊ページ200件まで。素材全体は原本と表示画像のdata URL文字数の合計を80×1024×1024以下に制限する。デコード後80MiBやメモリ使用量の保証ではない。
- PNG/ZIP/PDFの圧縮画像累計128MiBで停止する。小分けの範囲出力を使う。これはブラウザの最大メモリを保証する値ではない。

上限の実装は `src/domain/style.ts` / `styles.ts` / `special.ts`、`src/io/import.ts` / `assets.ts` / `raster.ts`。容量上限に達する全組み合わせの負荷試験は未実施。

## 配布と起動

ローカル起動に加えて、GitHub Pagesの静的試用版を配置する。原稿処理と保存は端末内のまま。配下URLで同梱フォント、組版/PDF素材Worker、ZIP/PDFを扱い、リリース・タグは作らない。手順・公開範囲・CIと全体ゲートの違いは[DEPLOYMENT](DEPLOYMENT.md)、R-44へ集約する。実際の配置状態はoutput/deploymentの証拠で確認する。
