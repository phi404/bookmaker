# 初回実装の依頼

**履歴資料**：この段階の計画・設計根拠を保存した文書。現行の機能は [CAPABILITIES](../CAPABILITIES.md)、操作は [UI](../UI.md)、今後の方針は [ROADMAP](../ROADMAP.md)。本文の「現在」「後続」「未実装」は当時の範囲を指し、恒久的な実装指示ではない。

このリポジトリで、外部で完成した原稿を本に整えるWebアプリの最初の経路を実装してください。

最初に `AGENTS.md` と `docs/PRODUCT.md`、`PRINCIPLES.md`、`ARCHITECTURE.md`、`TYPOGRAPHY.md`、`UI.md`、`ACCEPTANCE.md`、`HARNESS.md` を読んでください。

## 今回成立させるもの

TXT / 貼り付け → 内部文書 → A6（105×148mm）縦書き一段 → 自動ページング → PC見開き/スマホの確認 → PNG/PDF。

自然な標準明朝、段落字下げ、基本禁則、文字サイズ・行間・余白の調整を含めます。執筆支援、自由配置、他判型、二段組、特殊ページ、アカウント、クラウドを追加しないでください。ルビは次のMVP段階で必須ですが、今回のslice-1の必須にはしません。

## 実装前

技術構成、責務とデータフロー、CSSに任せる部分と独自に扱う部分、プレビュー/出力の共通化、フォントのライセンス、PDFの達成範囲を簡潔に説明してください。可逆的な通常の選択は目的に沿って進め、重要な未決事項の採用を `docs/DECISIONS.md` へ記録します。

## 実装中

- 文字・文書・BookStyle・RenderedPagesを混ぜない。
- 未対応情報を黙って捨てない。
- `tests/product/adapter.mjs`、UI接続点、開発サーバーを実装につなぐ。
- fixtureを使い、失敗を修正する前に再現テストを作る。
- 既存の検証を弱めたり、基準画像を無条件で更新したりしない。
- 旧プロトタイプを採用する場合は出典を記録し、このリポジトリで検証をやり直す。

## 完了時

lint、実際のtypecheck、本文/レイアウトテスト、PC/スマホE2E、固定fixtureの視覚確認、実際のPNG/PDF検証を行ってください。`npm run verify` の結果、動かす手順、実行環境、目視証拠と未達事項を報告します。未実装・未実行・失敗を完成扱いしないでください。
