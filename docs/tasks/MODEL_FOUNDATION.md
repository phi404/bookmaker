# 文書構造とスタイルの土台

**履歴資料**：この段階の計画・設計根拠を保存した文書。現行の機能は [CAPABILITIES](../CAPABILITIES.md)、操作は [UI](../UI.md)、今後の方針は [ROADMAP](../ROADMAP.md)。本文の「現在」「後続」「未実装」は当時の範囲を指し、恒久的な実装指示ではない。

2026-10-03。ユーザーが選択した範囲は「設計・ハーネスを更新し、文書構造とスタイルの土台まで実装する」。全体方針は [../PUBLISHING_MODEL.md](../PUBLISHING_MODEL.md)。旧 [PAGE_CONTROLS.md](PAGE_CONTROLS.md) は完了したMVPの履歴。

## 今回実装する縦切り

1. Sectionを持つ正本AST、安定ID、ソース投影、従来記法の互換。
2. 名前付き文字/段落/見出しスタイル、継承の検証、有限のプロパティ解決、個別変更と解除。
3. 本・章・ブロック等の意味的Scopeと、物理ページScopeの分離。一般化したRunning Elementの土台。
4. ASTとスタイルからWorkerへ渡して組版し、同じ結果でプレビュー・PNG/PDFを作る。
5. 新形式JSON/下書き、旧形式の移行。旧下書きは新形式で保存する前に端末内へ退避する。破損/未知形式は上書きしない。
6. 紙面またはソースで段落を選び、必要なときだけ段落スタイル・字下げ・揃え・太字・Keep with nextを変え、個別変更を解除する最小UI。

段落の字下げは原稿の空白を消さない。標準の自動字下げ無効、従来の判型・版面・出力寸法・保存保護を維持する。

## 今回実装しないもの

全文のリッチエディタ、Book/Assetsの全面UI改修、パネル幅変更、コマンド検索、特殊ページ生成/編集、画像/PDFの挿入、横書き/二段、数字の自動変換、目次生成、文字PDF/PDF-X、プリフライト。型の枠や計画だけを完成機能と表示しない。

## 独立した検証

前へ挿入・章の改名・段落の移動でID/Scopeが残ること、参照先の削除を診断すること、スタイル継承/循環/不明項目/優先順位、Override解除の非破壊性、Markdown構造/未知記法/元文字、正本ASTからのソース再生成、旧JSON/下書きの移行と原本退避を検証する。

MVPの本文ハッシュ・禁則・10万字・ルビ・寸法とPNG/PDF一致、両画面幅、破損保護をそのまま回帰させる。新しい操作は選択→個別変更→保存→再読込→解除まで検証する。基準画像は実差分が出た場合だけ目視し、まとめて更新しない。
