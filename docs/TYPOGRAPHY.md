# 組版の不変条件と規則

## 品質の基準

[W3C JLREQ](https://www.w3.org/TR/jlreq/) を品質の参照にする。全面的な準拠宣言ではない。対応/未対応の一覧は [CAPABILITIES](CAPABILITIES.md)、入力の読み方と正規化は [SOURCE_FORMAT](SOURCE_FORMAT.md)。

本文・見出し・ルビ親文字/読みの順序を守り、設定変更で欠落・重複・文字置換を起こさない。書式による数字表示も元文字を変えない。ページ番号・柱が本文や互いに重ならない。プレビューと出力のために別の行/ページ分割をしない。

## 標準と版面

標準はA6・縦書き・右綴じ・一段・白い紙。同梱Noto Serif JP Regularを本文明朝にする。太字はブラウザの合成。標準9pt・行送り1.8倍、天15/地16/ノド17/小口13mm。コンパクト8.5pt/1.65倍/13・14・16・12mm、ゆったり10pt/1.95倍/16・18・18・14mm。数値の正本は `domain/style.ts` のPRESETS。

標準A6の自然容量は36字×13行。字数/行数は本文の容量から計算し、指定した上限があれば実容量内で制限する。行を満杯にするための字間伸縮は行わない。

自動字下げは標準OFF。ユーザーが入れた全角空白と空行を使う。詳細でONにしたときだけ通常段落を1字下げし、既存の空白/開き括弧に二重適用しない。段落の局所字下げと段落全体/末尾の内側余白は別の属性。

## 行・段・ページ

縦書きは上→下、列は右→左。縦書き二段は上段を右→左、次に下段。横書き二段は左段を上→下、次に右段。行内の先頭/中央/末尾揃えは縦書きでは上/中央/下に作用する。

段落の前後空き・行送り・文字の大きさ/字間をmmへ解決して自動ページングする。容量より大きいインデントは本文が入るまで縮め、診断する。Keep with nextは次段落の文字サイズと前空きを含めて最初の行を確保する。一ページに入らない条件を無理な座標移動で満たさない。

見出しは通常最大1.15倍、狭い行送りでは隣の列/ルビとの衝突を抑える。長い見出しは分割する。版面Styleの境界は流し込みを区切り、特殊ページの後に続く本文はその構造の版面で再開する。

## 禁則と連続記号

独立した基本期待値は行頭禁止 `、。，．？！）］｝〉》」』】`、行末禁止 `（［｛〈《「『【`。テストは実装の集合を正解として取り込まない。基本の送り戻しと連続記号の分断抑制を検査する。

禁則文字だけが続く等、容量内で解けない入力でも文字を捨てない。違反ページ/ブロックを診断して目視対象にする。通常fixtureへ例外を広げて検査を回避しない。

`―` U+2015と`—` U+2014の連続部分は一本の線として描く。`ー` U+30FCは長音記号の字形を使う。ASCIIハイフンやマイナスを連続ダッシュへ置換しない。連続リーダ/ダッシュを通常の折返しで不自然に分断しない。

## ルビ・圏点

縦書きルビは本文の右側。親文字と読みの大きい方の長さを確保し中央に置く。行より長いグループは親文字の書記素に比例して読みを分け、両方を保持する。長い読みは縮小して診断する。これは熟語ルビ/モノルビの高度な規則ではない。

ゴマ/丸/白丸/三角の圏点を文字群へ置く。ルビと圏点が同時なら圏点を本文の左へ置く。英字の正立指定でも圏点を全角セルの中央に配置し、方向指定で日本語/ルビの親文字を横倒しにしない。

## 数字・欧文・書記素

自動は1桁数字の正立、2桁の縦中横、長い数字の横倒しを扱う。局所の縦中横/正立/横倒し/漢数字表示で元の数字列を変えない。英字の向きはASCII英字・数字へ適用し、日本語・括弧・ルビ親文字は通常の縦書き字形を維持する。

Intl.Segmenterの書記素を分割単位にする。結合文字・IVS・ZWJ・サロゲートペアを保ち、Unicode正規化を黙って行わない。ASCIIの字幅は同梱フォント由来のメトリクス、日本語は基本1emを使う。非ASCII欧文の厳密な字幅は未対応。単語/URLの改行候補は同梱@cto.af/linebreakのUnicode17規則で求め、日本語禁則・書記素・ルビの単位で制限する。書式が変わる位置を単語の切れ目にしない。行より長い分割不可単位は原文を保持して分け、診断する。

タブは4emの空き。制御文字は正本に保持し、描画時だけ制御記号へ変える。Unicode非文字/孤立サロゲートは描画時に〓。欠字・異体字はブラウザのフォールバックに依存し、正しい描画の保証や欠字検出はない。

## 開始面・白ページ・特殊ページ

見開きは右綴じで奇数通しページが左、左綴じで右。改丁（recto）は奇数通しページ先頭から始め、必要な白ページを実ページとして保持する。印字番号の開始値で改丁の偶奇は変えない。定義は[JLREQ 4.1.4](https://www.w3.org/TR/jlreq/#how_to_handle_headings_with_new_recto_page_break_and_new_column)を参照。対向面のないページ1や末尾の仮想面は表示用で、PDFへ追加しない。明示改ページの連続/末尾指定による白ページは実ページとして保持する。

左右共通用途では左右開始を次の本文ページ先頭として扱い、偶奇合わせの白ページを追加しない。診断と原指定を保持し、本へ戻せば開始面を再適用する。

独立した特殊ページは本文を確定して一ページを占有する。直後の改ページは既に生じた境界として扱い、余分な白ページを作らない。追加の連続改ページや開始面の条件は別に保つ。フロー画像は同じ本文ページ内の予約帯として生成する。

## 柱・番号・画像の診断

柱/番号は余白の帯へ配置する。解決後のPageStyleと表示条件に対して、サイズ・端からの距離・同位置の衝突を検査する。非表示の要素の衝突を理由に本文の書式を拒否しない。長い柱は版面の幅へ縮める。

画像は生成された配置と実ピクセルから実効dpiを求める。原PDF寸法・想定塗り足し・枠外/溢れを診断するが、CMYK・フォント・PDF/Xの検査とは区別する。裁ち落とし画像も現在の出力は仕上がり寸法まで。

## 役割分担と限界

CSS writing-mode / text-orientationとSVGは字形を担当する。TypeScriptはページ配列・Scope・行/段分割・文字群の位置を担当する。ブラウザ標準だけで寸法・ページ対応・出力一致が保証されるとは仮定しない。

約物の半角詰め、ぶら下がり、熟語/モノルビ、高度な均等配置、欠字検出、多言語の実測字幅は未対応。次の改善は実書籍または反例fixtureから始める。画像PDFの一致を、日本語組版の全規格準拠や印刷所の合格へ読み替えない。

## 段落の最少行数と仕上げ

CSS Fragmentationのorphans/widowsを参照し、段落が段/ページをまたぐ前後の最少行数を扱う。前後空き・可変行送り・一二段を含む予約容量で分け、満たせない小さな版面では診断する。元文字とルビを削って成立させない。

番号系列と末尾白ページは最終的な同じページ列へ解決する。図の説明は画像の予約帯へ収め、文字溢れは出力前診断へ渡す。本文の座標調整で空きを作らない。

U+200B/C/D・U+2060・U+FEFFは単独の制御単位として幅0、NBSP U+00A0は同梱書体の半角空白幅で扱う。U+2028/U+2029は幅0の明示行区切りとして保持する。文字を削除したり保存上のLFへ変換したりしない。Unicodeの必須区切りを優先し、それ以外へ日本語の禁止位置を加える。Unicode17公式の全ケースはライブラリ層で検査し、製品独自の容量/ルビ/禁則調整は別の反例で検査する。Unicode18全面準拠や正確な全書体メトリクスの宣言ではない。
